面向开发、测试与验收人员的 AI 测试工作台。接入项目与需求，确认测试范围，驱动浏览器和结构化执行器运行检查，收集证据，并在发现问题后进入沙盒修复与回归。

## 项目是做什么的

用户可以提供本地代码目录、应用地址、需求、Git diff 或缺陷上下文。系统的目标是把这些输入组织成可以执行、可以审核、可以追溯的测试任务：

1. **接入项目**：识别技术栈、启动入口、依赖、页面和接口。
2. **确认范围**：形成业务功能与测试路径，展示前置条件、断言和权限，交由用户审核。
3. **执行检查**：通过 Playwright，以及受约束的 API、数据、任务和命令执行器完成检查。
4. **保存证据**：关联截图、DOM、网络、日志、Trace、断言、Run 和 Attempt。
5. **判断结果**：由机器规则形成结论，按需使用模型解释复杂证据，并支持人工复核。
6. **修复与回归**：在源码副本中编辑补丁，重新验证，最后导出或按权限应用修改。

例如，需求是“任务筛选只能显示已完成任务”：完整验收需要真的启动应用、点击筛选、核查页面和接口数据、保存证据；如果发现缺陷，还要证明补丁使同一项检查从失败变为通过。

## 已有模块与当前缺口

| 环节 | 已有实现 | 必须补齐的关键问题 |
| --- | --- | --- |
| 项目接入 | 项目检测、运行配置、源码与依赖缓存 | 项目切换的异步响应串扰；生产存储与路径一致性 |
| 测试规划 | 需求对话、业务功能/路径编译、规划清单 | 用户删除或新增的路径与实际执行范围不一致 |
| 身份与权限 | OIDC、角色/项目授权、凭据存储 | 登录入口未接通；部分请求硬编码组织或遗漏 Bearer；直接文件下载缺项目授权 |
| 执行与恢复 | LangGraph、父子任务、BullMQ、租约、执行器 | 跨进程取消、父任务超时收尾与重启恢复仍需真实验证和修复 |
| 证据与判定 | Artifact、完整性校验、证明图、机器 Gate、LLM Judge | 下载权限与指标真实性；独立业务判定不能沿用 Agent 自评 |
| 修复与交付 | 沙盒副本、编辑、Diff、复测、导出与应用 | 再次编辑未使旧验证失效；验证没有完整绑定补丁版本 |
| 生产运行 | PostgreSQL、Redis、S3/MinIO 与容器配置 | 只读容器内仍有本地写入；控制服务与执行节点的职责、网络和共享状态未完全贯通 |

技术栈识别包含 Node.js、Python、Go、Rust、Java、Ruby、PHP 和静态站点的适配逻辑。**识别出框架或启动命令，不代表该类项目已经在沙盒中完成业务验收。** 外部服务、私有依赖与测试账号仍需实际配置。

## 快速开始

### 环境要求

- **Node.js 24**，与仓库 `.nvmrc` 一致。根 `engines` 声明的 `>=22.5` 低于当前部分前端依赖的要求，建议使用 24。
- npm，以及首次安装依赖所需的网络访问。
- Playwright Chromium，用于实际浏览器执行。
- Docker Desktop 或 Docker Engine，用于外部项目隔离运行、修复及容器化验收。仅启动开发 UI/API 不要求 Docker。
- 使用模型规划、浏览器决策或 AI 修复时，需要自行配置真实模型服务和有效凭据。

### 安装与启动

```bash
git clone https://github.com/ZZX0109/ai-test-officer.git
cd ai-test-officer
# 已安装 nvm 时可执行 nvm use；否则先安装 Node.js 24。
npm ci
npm run init:local-config
npx playwright install chromium
npm run build:packages
npm run dev
```

`init:local-config` 创建本地加密凭据配置与项目外的 master key；已有配置会保留。不要提交 `.env`、真实 API key、master key 或 `config/local-secrets.json`。

`npm run dev` 启动以下开发服务：

| 服务 | 默认地址 |
| --- | --- |
| Workbench | <http://127.0.0.1:6174> |
| Agent API | <http://127.0.0.1:4317> |
| 内置演示 Web | <http://127.0.0.1:6173> |
| 内置演示 API | <http://127.0.0.1:6172> |

内置演示应用使用仓库里的种子数据与演示服务，适合熟悉界面，**不作为真实外部项目能力的证明**。开发服务地址不等于生产部署方案。

```bash
npm run health:check
npm run stop:dev
# 需要后台运行开发服务时：
npm run dev:background
```

### 第一次使用

1. 打开工作台，进入“配置与证据”中的“项目与运行配置”。
2. 选择实际项目目录，识别并核查技术栈、启动命令和运行地址。
3. 配置必要的模型、目标系统账号和外部依赖，准备隔离运行环境。
4. 启动项目，确认工作台能访问实际页面。
5. 描述测试目标，审查测试范围、断言与权限，再确认执行。
6. 查看具体步骤、真实证据与结论；失败时再进入修复工作区。

### 模型配置

点击工作台顶部的模型配置按钮，填写服务地址、模型和 API key，保存并进行连接测试。项目包含 Chat Completions、Responses 与 Anthropic Messages 的传输适配，具体服务是否支持所需结构化输出和工具调用，需要实际验证。

连接测试只证明对应探测请求成功；声称 AI 规划、执行或修复成功时，还必须检查该阶段的真实调用记录、输出是否被执行，以及对应业务证据。缺少凭据或模型失败时，不应使用演示结果替代。

## 真实验收标准

正式验收需要锁定项目源码、依赖、执行镜像、测试数据、确认计划与模型配置版本，并保存本次运行的可核对证据。

- 使用真实项目构建、进程、浏览器、API 和数据服务；不得以固定成功响应、空实现、预录操作替代。
- 声称 AI 参与的阶段必须有真实模型调用及输出被消费的记录。
- 独立业务断言在运行前确定，不能复制 Agent 的自评结论，也不能被修复 Agent 删除或降低要求。
- 修复必须证明同一缺陷在修复前失败、修复后通过、撤销补丁后再次失败；追加无关注释不算修复。
- 补丁变化后旧验证失效；导出或应用的字节必须与已验证版本匹配。
- 缺少必需依赖、权限或证据时，记录失败或阻塞，不能跳过后仍判发布通过。
- 准确率、召回率与误报率需要独立标注数据；没有依据时标为不可计算，不能填零或用执行成功率代替。

现有部分 external evaluator 只核对结构或沿用系统结论，部分 repair evidence 脚本只证明编辑操作。这些结果不能用于证明业务判断正确或真实缺陷已修复，具体问题见[方案中的验收口径修正](docs/remediation-plan.md)。

## 开发与检查

```bash
npm run build
npm run lint
npm run quality:contracts
npm run size-guard
npm test
npm run typecheck
git diff --check
```

完整质量入口为 `npm run quality`。当前已知 size-guard 失败和 Agent 测试提前退出问题需要先修复；不能因为某条命令退出码为 0 就标记全部通过。

以下脚本依赖额外服务或凭据，需核查实际执行范围和生成证据：

| 命令 | 用途与边界 |
| --- | --- |
| `npm run test:workbench-e2e` | 工作台演示链路，要求服务和真实模型凭据；不是任意外部项目验收 |
| `npm run acceptance:production` | 隔离生产依赖栈检查，不能替代真实业务用例 |
| `npm run acceptance:external:preflight` | 外部项目预检查，构建/启动成功不等于业务正确 |
| `npm run contracts:generate` | 生成 OpenAPI 与客户端契约 |
