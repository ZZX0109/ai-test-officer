# AI Test Officer CI Contract

The CI gate writes these stable files:

- `reports/gate.json`: machine-readable pass/fail/coverage/runtime decision.
- `reports/junit.xml`: JUnit-compatible single-testcase gate result for CI test report publishers.
- `reports/pr-annotation.md`: human-readable PR summary.
- `reports/pr-annotations.json`: annotation payload for PR integrations.
- `reports/artifact-upload-manifest.json`: files that should be archived by CI.
- `reports/run-bundle.zip`: portable run download bundle generated by the Node CLI.
- `reports/run-bundle-download-manifest.json`: archive index with `included`, `missing`, `path_escape`, `unreadable`, and `reference_only` artifact states.

Even when the CLI fails before a browser run starts, for example `runtime_unavailable` or an unexpected CLI exception, it still writes `gate.json`, `junit.xml`, `pr-annotation.md`, `pr-annotations.json`, and `artifact-upload-manifest.json` so CI can archive a machine-readable failure.

The download bundle includes the run bundle, readable reports, artifact integrity report, and inline evidence artifacts. HTML reports inside the zip rewrite `/artifacts/...` image/link references to archive-relative paths, so an extracted `runs/<runId>/report.html` can be reviewed offline with its screenshots. Large trace/video artifacts follow a reference-only policy by default, so they stay out of `run-bundle.zip` and are listed in both `run-bundle-download-manifest.json` and `artifact-upload-manifest.json` for separate CI archival. Tune the inline threshold with `RUN_BUNDLE_MAX_INLINE_BYTES`.

Exit codes:

- `0`: pass.
- `1`: release gate failed.
- `2`: harness gap or insufficient coverage.
- `3`: runtime unavailable.
- `4`: unexpected CLI error.

By default, `needs_review` exits with `2` because it means the harness or evidence was not strong enough for an automatic release decision. Set `STRICT_RELEASE_GATE=1` to treat `needs_review` as a release gate failure and exit with `1`.

Gate policy file:

- Default path: `ai-test-officer.gate.json`.
- Override path: `CI_GATE_CONFIG=/path/to/gate.json`.
- `strictGate`: treat `needs_review` as exit `1`.
- `flakyMode`: `warn` maps flaky evidence to exit `2`; `fail` maps flaky evidence to exit `1`.
- `quarantinedScenarios`: matching non-pass scenarios exit `2` with `policyReasons` instead of blocking as release failures.
- Invalid gate config fails the CLI with exit `4` and still writes the standard CI failure artifacts.

For real project smoke, set `PROJECT_ID` to a `data/projects/*.json` adapter entry and keep secrets in environment variables or Credential Center references, not in project manifests.

Report retention:

- Dry-run: `npm run reports:retention`
- Apply deletion: `npm run reports:retention:apply`
- Archive instead of delete: `npm run reports:retention:archive`
- Tunables: `REPORT_RETENTION_DAYS=7`, `REPORT_KEEP_RUNS=20`, `REPORT_KEEP_LOOSE_ARTIFACTS=30`, and `REPORT_MAX_REPORTS_MB=100`.
- `npm run demo:verify` runs archive-mode retention automatically after writing the demo verification result. Set `SKIP_REPORT_RETENTION=1` when you intentionally need to keep every intermediate artifact for debugging.
- Override paths for automation/tests: `REPORTS_DIR=/path/to/reports`, `REPORT_ARCHIVE_DIR=/path/to/archive`, and `AI_TEST_OFFICER_HOME=/path/to/storage`.

The retention job keeps the latest run pointer, preserves SQLite audit data, prunes orphaned run screenshots/traces, bounds loose artifacts such as videos and commit-check reports, and writes `reports/retention-manifest.json` for auditability. Archive mode writes outside the project by default under `~/.ai-test-officer/reports-archive/<project>/` so the active workspace can still shrink; set `REPORT_ARCHIVE_DIR` when CI should upload/archive to a controlled path.
