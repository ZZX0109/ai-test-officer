# 测试工程内在逻辑与当前实现

这套系统的判断链路必须是“需求/变更 → 可识别的业务能力 → 可执行路径 → 运行时动作 → Oracle 结果 → 证据 → 门禁”，而不是“模型说测过了 → 页面显示成功”。

## 一条完整测试链路

1. **接收测试目标**：读取需求、缺陷、代码变更和项目边界，确认目标项目、运行环境、凭据和权限。
2. **建立项目事实**：解析项目清单、页面入口、API operation、数据源、后台任务和启动命令；未知信息保留为未知。
3. **识别业务能力**：从页面、用户动作和业务流程形成能力；API、数据表、handler、健康检查等只作为实现证据或技术资源。
4. **生成业务路径**：为每个能力拆出入口、关键动作、预期结果、前置条件、权限、风险和证据要求。
5. **设计行为覆盖**：除 happy path 外，明确负向、边界、权限、状态转换、数据一致性、幂等和恢复维度。
6. **运行时绑定**：把静态路径绑定到真实页面控件、声明的 API、只读数据模板或后台任务；绑定失败必须变成明确 coverage gap。
7. **拆分执行 Run**：每条可执行路径有独立 Child Run、预算、超时、尝试次数和证据集合，父 Run 只聚合子 Run 的事实。
8. **调用 LLM**：Planner、Browser Agent、Judge 和 Assistant 通过服务端 ContextLayer 获取项目、Run、证据、失败历史和修复历史；上下文脱敏、分层和限额。
9. **执行受控动作**：LLM 只能提出结构化动作；Tool Gateway、权限策略和浏览器绑定层决定动作是否允许，危险动作需确认。
10. **验证 Oracle**：Oracle 必须对真实的 DOM、URL、网络、数据或任务状态执行判断，并挂接 assertion/evidence 引用。
11. **形成业务门禁**：业务能力只有同时具备可执行入口、关键动作、预期结果、已执行 Oracle、有效证据且没有未解决高风险路径才可通过。
12. **生成轨迹与报告**：持久化 LLM 输入/输出、工具调用、动作、Oracle、证据和父子 Run 关系，轨迹是事实审计，不是模型思维文本。
13. **失败归因与修复**：按环境、测试脚本、产品缺陷、证据不足等分类；修复只在沙盒中生成，必须交付 patch、影响说明、定向验证、回归验证和合并资格。
14. **回归与度量**：重新执行受影响路径，记录业务识别准确率、需求覆盖、Oracle 覆盖、行为覆盖、缺陷发现率、误通过/误失败、诊断耗时和修复后回归通过率。

## 本项目本轮已完成

- 业务能力编译器区分 `business-capability / page / api / technical-resource / runtime-observation`；API-only 路径默认不会成为业务功能，可通过 `ProjectManifest.businessCapabilities` 显式映射。
- 业务级 Machine Gate 已接入动态浏览器证明和普通结构化运行；动态执行后会把真实动作和 Oracle 回写到 coverage，避免“界面显示执行、门禁没有预期结果”。
- ContextLayer 已接入 Planner、Browser Agent、Judge、Assistant 和 Tool Gateway，并真正返回预算裁剪后的结果；聊天接口有持久化 Run 时优先使用服务端事实。
- Experience Memory 支持真实 OpenAI-compatible embedding 与关键词混合检索；未配置 provider 时明确降级为 `keyword-v1`，不再生成哈希伪向量。
- CoverageItem 增加行为维度与实际执行维度，路径执行不会自动冒充已覆盖所有负向、权限或恢复场景。
- Repair Session 增加可交付物：patch SHA-256、影响范围、定向/回归验证状态、验证证据和合并资格。
- Run 结果在普通执行和动态浏览器执行收口时计算可由持久化事实支撑的指标。路径/风险覆盖从计划与执行状态计算；误报率、误通过率、识别 F1、测试成功率、耗时、Oracle 与证据覆盖要求显式标签或归属信息，缺少分母时保持未提供，不以 0 代替。需求覆盖只接受独立需求样本，不把路径数量当成需求标签。

## 仍需外部配置或持续验证的事项

- 配置 `MEMORY_EMBEDDING_URL`、`MEMORY_EMBEDDING_API_KEY`、`MEMORY_EMBEDDING_MODEL` 后，使用 50 条 sealed 数据集跑 Recall@5/10、MRR、误召回率和来源可追溯性基线。
- 用真实异构项目做端到端盲测，确认页面识别、能力归并和运行时绑定不会只在内置 demo 上成立。
- 为行为覆盖提供每个项目的业务标签/期望矩阵，否则系统只能诚实报告“已执行的维度”，不能推断产品需求完整度。
- 持续采集误通过、误失败、缺陷发现率和修复后回归结果；没有人工标注或回归样本时，相关指标保持为空而不伪造数值。
- 普通 Chat Completions 的用户可见 token 流式输出、全局父子 Run 连续轨迹和原生 tool-calling 兼容性仍可继续增强，但不影响本轮确定性门禁。
